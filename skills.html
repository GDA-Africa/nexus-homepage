@nexus-framework/skills · v0.3.0

Every skill in the registry.

49 skills across 10 framework sets. A skill is a markdown file that answers the question every agent gets wrong on its own: how do we do things here? They install into .nexus/skills/ as plain files, readable by any tool, and agents reach them through nexus_list_skills → nexus_get_skill.

Reference, what the agent reads

Consulted before an artifact is produced. Patterns, anti-patterns, a worked example. Can be skimmed and partially applied with no harm.

Procedure, what the agent runs

A discipline with a start, an end, and a completion criterion: an interview, a diagnosis loop, a review pass. A procedure that is half-run has not been run. New in SKILL_SPEC v2.

Write your own

Registry skills are a starting point. The ones that pay off most are the ones only your team can write, the convention no config file confesses, the gotcha that cost someone a day. Custom skills live in .nexus/skills/custom/ and are never touched by an upgrade.

$ nexus skill new deploying-a-worker Category: procedure Invocation: model ✓ .nexus/skills/custom/deploying-a-worker.md (status: draft) $ nexus skill status # validates every skill against SKILL_SPEC v2
