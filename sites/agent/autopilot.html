nexus-agent.web.app · focus 3 of 3

Hand off a task and walk away.

You don't always want to chat back and forth. With nexus agent "<task>", you can dispatch an autonomous agent from your terminal, CI script, or editor. It wakes up grounded in your active plan, writes code and tests, ticks the checklist, and exits cleanly.

terminal: headless execution
$ nexus agent "add rate limiting to the login route"
[stderr] NEXUS agent starting: project api-core, plan harden-auth
[stderr] Brain context injected at step 1: active plan, rules, 2 lessons, vitals
[stderr] Next step: 3. Rate-limit POST /login
[stderr] Applying lesson: reuse the shared Redis client instance
→ edit src/routes/login.ts (+38 lines)
→ run npm test (122 tests passed ✓)
→ nexus_plan_tick { id: "harden-auth", step: 3 } ✓ Step 3 ticked
[stdout] ✓ Finished: added rate limiting to POST /login with 14 passing tests. Next up: Step 4. Lockout email alerts.

Built to pipe and script like any Unix command.

⚡
Reasoning on stderr, answer on stdout

Progress logs and tool calls stream to standard error so your terminal stays informed. The final result prints cleanly to standard out, making it easy to pipe to other scripts or save to a file.

🛡️
Never starts with amnesia

Generic headless tools burn tokens reading random files. NEXUS injects the active plan, next checklist step, and matching gotchas right at step 1 so zero tool calls are wasted on orientation.

🤖
Ready for GitHub Actions & CI

Run automated bug fixes or migration scripts in your CI pipeline. When the agent finishes, it exits with exit code 0 on success, or a non-zero code if tests failed.

Example: Automated GitHub Action

Here is how you can use NEXUS Autopilot inside a GitHub Action to automatically verify and resolve dependabot issues or run background audits:

# .github/workflows/nexus-autopilot.yml name: Nexus Autopilot Task on: [workflow_dispatch] jobs: run-task: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - run: npm install -g @nexus-framework/cli - run: nexus agent "upgrade zod to latest and update affected schemas"
