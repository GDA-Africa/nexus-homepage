the problem

Every session starts from zero.
Unless the engine remembers.

Every time, you explain your project again: the plan, the rules, the past mistakes. Agents burn tokens asking "what are we working on?", and you cannot see what they actually knew when they made a call. A stateless engine is powerful, and blind.

A stateless agent BLANK SLATE
  • Starts every turn with zero memory of the plan or the architecture
  • Spends its first tool calls just getting oriented
  • Plans go stale unless a person updates them
  • Helper agents run in the background, a black box
  • Cryptic provider errors, manual JSON for local models
Nexus Harness GROUNDED
  • Plan, next step, rules, lessons and vitals arrive at step 1 of every turn
  • Zero tool calls wasted on orientation
  • The agent ticks its own plan, every action recorded
  • Watch delegated helpers work live, side by side
  • Plain-language errors, local models in one click
three ways in · one cli

Run it the way you work.

Zero orientation calls

No "what are we working on?" round trips. The plan slice, matching knowledge, trigger-matched skills and a health snapshot ride in with the turn.

Scoped, not dumped

The same bounded, token-budgeted context pack that nexus_get_context composes, ranked by relevance to the task, never your whole knowledge log.

Markdown stays the truth

It is read straight from your .nexus/ files. Edit a doc, and the next turn knows.

Less repetition, fewer wrong guesses, faster results.

capability 02 · in-process brain tools

The assistant manages the project itself.

It reads and updates the plan, ticks off finished steps, looks up past decisions and runs health checks. 16 NEXUS tools run inside the harness, with no separate helper process and no extra hop. Every call lands in the harness's own append-only session log and token accounting.

system topology

The brain owns meaning.
The harness owns execution.

The CLI never depends on the engine. The harness imports the brain through the CLI's public ./mcp export and mounts it as two plugins. Claude Code, Codex, Antigravity IDE and Cursor keep reaching the same brain over nexus mcp. The harness is another way to run, not a replacement.
