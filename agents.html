first principles

What is an AI agent, actually?

An agent is an AI model given a role, tools, and a loop: it perceives state, decides, acts through tool calls, and checks the result — repeatedly, until the job is done. The difference between a chatbot and an agent is that the agent does things: edits files, runs tests, updates trackers.

Modern coding clients (Claude Code, Codex, Cursor) go further with subagents — specialized roles you can hand work to. But out of the box those roles are generic: "you are a code reviewer" knows nothing about your conventions, your past bugs, your current plan. That's the gap NEXUS closes.

Generic subagent STATELESS
  • "You are a code reviewer" — reviews against vibes
  • Every tool available to every role — no separation of duties
  • Forgets everything between sessions
  • Marks its own homework — self-review is the weakest review
NEXUS contextualized agent BRAIN-GROUNDED
  • Reviews against your recorded conventions, citing knowledge entries
  • Least-privilege tool allowlist — the reviewer literally has no write tools
  • Resumes the durable plan exactly where work stopped
  • Separation of duties — the test-writer verifies others, never itself
the nexus implementation

Agents are a brain primitive.

Each agent is a markdown definition in .nexus/agents/ — frontmatter for the machinery, a working agreement for the behavior:

--- agent: nexus-test-writer role: verification triggers: ["write tests", "verify", "step complete"] tools: read: [nexus_wake, nexus_get_vital_signs, nexus_get_skill, …] write: [nexus_plan_note, nexus_add_knowledge_entry] # least privilege context: docs: [06_test_strategy.md] # its context recipe knowledge_categories: [gotcha, pattern, convention] handoff: { after: nexus-implementer } --- ## Mission · ## Working Agreement · ## Definition of Done · ## Anti-Patterns
🏗
nexus-implementer

Works the active plan's next unchecked step. Never re-derives an existing plan. Hands finished work to the test-writer — never self-certifies.

🧪
nexus-test-writer

The keystone. Detects your test setup via live sensors; writes tests matching your strategy doc; asks before installing test infra — never silently; records waivers visibly when you decline.

🔍
nexus-reviewer

Reviews against recorded conventions, citing the exact knowledge entries. Read-only by design — findings go in the review, not the brain.

📚
nexus-doc-keeper

Keeps the brain truthful: progress log, knowledge entries, doctor triage. Stale brains are worse than no brains.

Same ownership model as skills: core/ regenerates on upgrade, custom/ is sacred (yours, never touched — and overrides core by name), community/ installs from the registry. Generated as Claude Code subagents in .claude/agents/, degraded to "Agent Roles" tables for every other client. nexus agent sync regenerates the views; the definition is the only source of truth.

accuracy, enforced

The verification gate: D11.

Every framework says agents "should" test their work. NEXUS makes it structural: a plan can't quietly reach done without test evidence or an explicit, human-approved waiver in its Evidence section.

🚦
Doctor D11 — Unverified Done

The 11th drift check flags every completed plan with an empty Evidence section. Surfaces in nexus doctor, in CI PR comments, in briefs.

⚠️
plan done warns

Completing with no evidence prints the warning and the exact commands to fix it — record results or record a waiver.

🤝
Humans stay the boss

Waivers are first-class: "WAIVER: docs-only change, approved by Halton." Skipping verification is visible, never impossible — same doctrine as the wake handshake.
