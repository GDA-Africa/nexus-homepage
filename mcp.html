first principles

What is MCP, in one breath?

MCP, the Model Context Protocol, is a standard way for AI models to call tools and read data from the outside world. Think of it as USB for AI: instead of every app inventing its own plugin system, an MCP server exposes capabilities ("tools") with typed inputs and outputs, and any MCP client, Claude Code, Claude Cowork, OpenAI Codex, Cursor, can discover and call them. The model doesn't scrape or guess; it makes a structured call and gets a structured answer.

🔌
Tools, not prompts

Each capability has a name and a JSON schema. The model calls nexus_wake {} the way your code calls a function, arguments validated, result typed.

🔍
Discoverable

Clients ask the server "what can you do?" and get the full tool list with descriptions. No configuration beyond pointing at the server.

🤝
Universal

One server works with every MCP client. Write it once; Claude Code, Codex, and Cursor all speak to it the same way.

the nexus implementation

Your project's brain, served.

Every NEXUS project carries a .nexus/ brain, structured docs, an append-only knowledge base, durable plans, skills. Before MCP, agents were told to read those files. Instructions get skipped; whole files flood the context window; one typo in hand-edited frontmatter corrupts the brain.

nexus mcp turns the brain into a server. Generated projects ship a .mcp.json that registers it, so clients connect automatically:

{ "mcpServers": { "nexus-brain": { "command": "npx", "args": ["-y", "@nexus-framework/cli", "mcp"] } } }
🧠
16 schema-validated tools

13 reads (wake, context, knowledge, plans, sensors, skills, agents) + 3 writes (plan tick/note, knowledge entry). Writes reuse the CLI's own parser, malformed brain state is impossible, not just detectable.

📄
Markdown stays the truth

No database, no daemon. The server is spawned per client over stdio and exits with it. Everything it serves is a file you can read, diff, and version.

🪪
Provable sessions

nexus_wake issues a deterministic token derived from brain content + date. Agents echo it; nexus doctor flags sessions that skipped it.

🎯
Targeted, not torrential

nexus_query_knowledge returns the 2 relevant gotchas, not 200 lines. nexus_get_context composes one budget-capped pack per task.

mcp × agents

The protocol is how NEXUS orchestrates agents.

In v1.1, NEXUS defines specialized agents, implementer, test-writer, reviewer, doc-keeper. MCP is the nervous system that coordinates them: every handoff, every piece of context, every progress update flows through the same tool surface.

01 · IDENTIFY
Wake as a role

nexus_wake {agent}, the session records which agent is working. Accountability from call one.

02 · COMPOSE
Context on demand

nexus_get_context assembles the plan slice, matching knowledge, and skills for that agent's recipe, one call, one pack.

03 · ACT
Validated progress

nexus_plan_tick / note, work state advances through the parser, never hand-edits.

04 · HAND OFF
Durable relay

The next agent wakes, reads the same plan, picks up exactly where the last one stopped. The brain is the baton.

Because the state lives in markdown and moves through MCP, orchestration survives across sessions, across days, and across different AI products, an implementer in Claude Code can hand off to a reviewer in Cursor without losing a step.

what you get

Why this beats "please read the docs."

⚡
Faster sessions

One wake call replaces reading three files in full. No more re-deriving plans every session, the single biggest source of wasted agent work.

🎯
More accurate work

Agents decide with the gotchas that matter in context, not buried at line 180 of a file they skimmed.

🛡
Unbreakable brain

Schema-validated writes ended the entire class of "hand-edited frontmatter corrupted the brain" bugs.

📏
Compliance is structural

"READ index.md EVERY TIME" was a rule agents could skip. Tools they naturally reach for can't be skipped, and wake makes skipping visible.
